# Saved single-block M3-CS reader: current 0.0.31.9001 contract

This isolated increment adds reader execution capability
`bmeas_saved_m3cs_reader_v1`. It does not change the portable producer profile,
capability list, capsule identity, source paths, ancestry, nested seals, or
archived bytes. Current source tests use deterministic R execution doubles, including
all-fixed profiles. A separate prior-source saved-reader native seam gate passed
12 iid/centered assessment cells with 24 recorded fixed_param calls in 64.57 seconds.
That gate predates the final export repair, excludes all-fixed, and is not an OS
process census or independent source-to-binary proof. No posterior/scientific
validation, HMC or new native execution is claimed by this release qualification.
See SAVED_COGNITIVE_WORKFLOW_zh.md and the accompanying release VALIDATION.md.

## Accepted contract

- Exactly one canonical pinned main-API M3-CS observation block.
- Conditional response or population prediction using the saved full roster,
  operand map and supported iid or same-N centered person law.
- Ten response cells, with active categories 1, 2, 3, 4 and 10, retained options,
  and fixed observed row totals. Existing complete-work budgets apply.
- Complete portable envelopes and freshly reopened archives. Detached contexts
  and private consumer views are not new public execution entry points.

The reader verifies genuine detached schema without fabricating a live
`bhmm_spec` class or resealing. Portable planning checks declarative schema and
maps under the saved context allowances, but does not hash or open resource,
posterior, executable, or provider files. It does not authenticate the capsule
identity. Archive planning retains its existing fresh archive integrity reopening.
Neither planner constructs a simulator or compiles code.

## Explicit current execution binding

`assess_measurement_fit(..., checks="ppc", level=..., draws=..., seed=...,
budget=..., simulator=...)` accepts an explicitly provided
`bmeas_m3cs_simulator` with version `bmeas_m3cs_rng_v2`. Canonical generated source,
source hash, pinned resource digest and executable digest must agree. The source
text remains byte-identical to the existing live rng_v2 source. These are
consistency checks on the explicitly supplied capability and current files;
the executable digest alone is not independent source-to-binary authentication
and does not prove a new compilation history.

An optional `simulator$resource_file` supplies the current resource location for
saved execution after relocation. Its bytes must match the pinned SHA-256. If
omitted, the historical resource path is used as a current lookup, without any
claim that the file still exists. This optional binding never edits the saved
resource descriptor or historical paths. The result records the current resource
binding separately in mutable result metadata. Moving a simulator executable
likewise requires its explicit model binding to resolve to matching bytes; the
reader neither searches for an executable nor manufactures a new one.

Before any resource or executable access, assessment validates the full immutable
capsule, adverse original evidence, detached schema, full forward design, support
and predictive budgets. Archive executions continue to use relocated posterior
member hashes, the explicit streaming policy and owned acquisition transaction.
Copy-only report caches, RNG restoration, current-input receipts and failed
attempt semantics remain in force. A successful check does not upgrade original
computation, inference or posterior-origin evidence.

## Still excluded

Routed/full M3, multiple cognitive blocks, mixed cognitive/basic blocks, EZ/SDM,
arbitrary adapters, implicit simulator construction, compilation, refitting and
source-path rewriting remain excluded. The generic experimental/EZ gate is
unchanged. The recorded prior-source native gate described above has a separate
bounded approval and evidence trail; it was not rerun for this release.

## Strict producer admission repair

The original reader-only candidate could not export the historical all-fixed
empty correlation_affine_cells table. Version 0.0.31.9001 now admits exactly that
eight-column typed-empty table only when the entire context has zero components
and no component/parameter correlation cells. Cached correlation metadata must
match the validated scientific table. No table, seal or producer capability is
rewritten. All-fixed live/portable/relocated-archive flows have deterministic
R-double coverage; no all-fixed native saved-reader qualification is claimed.

The exact revised-EZ provenance extension is also retained under strict pinned
schema checks. Export success does not permit EZ PPC or detached backend routes.
